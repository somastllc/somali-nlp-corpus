# Corpus run — 2026-10-19 (16 sources)

Measured build of the sixteen-source Track A corpus, after the deep-clean fixes and the
removal of Somali TinyStories. Every figure below comes from the per-run files under
`reports/` (not tracked in Git) or from `tokenizer/*.json`.

**Machine:** Intel Core i7-1185G7, 8 logical CPUs, 31 GiB RAM, Linux. No GPU is used; every
stage is CPU-bound. This is a smaller machine than the 2026-09-24 run (16 cores, 64 GB), so
wall times are not comparable.

## What changed since 2026-09-24

- **Somali TinyStories removed.** Its dataset card has no license.
- **HTML tags** no longer join words: block-level tags (`<br>`, `<p>`, `<div>`, ...) leave a
  line break when stripped.
- **OPUS cleanup** removes only a complete trailing tag instead of cutting everything after
  the last `<`.
- **Length floor re-applied** after deep clean (25 words for documents, 5 for sentences).
- **Stale quality flags** (`html_remnant`, `mostly_numbers`, `high_symbol_ratio`) are
  recomputed from the final text, so repaired records are no longer left on review.
- **Exact duplicates created by deep clean** are dropped in the deep-clean writer, first
  seen wins, across all sources (53,269 records in this run).
- **Paragraph dedup** compares word order, not vocabulary.
- **A lone carriage return** becomes a line break instead of being deleted.
- **Near-dedup memory:** the stage no longer holds document text in memory (see below).

## Timings

| Step | Wall time | Notes |
| ---- | --------: | ----- |
| Downloads (finepdfs, fineweb-2, somali-dataset) | 1 min 41 s | the other 13 sources reused the 2026-09-24 raw files |
| Pipeline: merge + exact dedup | 7 min 27 s | |
| Pipeline: clean | 6 min 37 s | 8 cores |
| Pipeline: language ID | 1 h 20 min | 8 cores; lingua-bound |
| Pipeline: deep clean | 1 h 4 min | 8 cores |
| Pipeline: near dedup | 5 min 17 s | second attempt, after the memory fix |
| Full-corpus tokenization (v2) | 13 min 30 s | `tokenize_corpus.py`, 7 workers |

The first near-dedup attempt was killed by the kernel OOM killer at 18 GB resident memory,
because it held every document-class record in memory next to its shingle set and MinHash
signature. It now keeps only each document's shingles, length, and id while clustering and
reads the input a second time to write the output. Output was byte-identical to the previous
implementation on a 550,000-record sample, with 44% lower peak memory. The deep-clean
output was intact, so only near-dedup was re-run.
